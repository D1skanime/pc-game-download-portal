# Quick Task Plan

**Goal:** Make manual description editing an explicit pencil action in the ROM and scoped PC DLC overviews. The overview must present the already-resolved description as ordinary read-only text, while the existing `LocalizedDescriptionEditor` opens only after the permission-gated edit action is activated.

**Scope:** Keep this UI-only. Reuse `LocalizedDescriptionEditor.vue`, `RDialog`, `RBtn`, the existing `rom.edit` checks, locale/resolution props, optimistic-version props, refresh events, and both existing mutation services. Do not change API routes, payloads, stores, composables, or backend logic. Preserve all unrelated PC DLC overflow actions.

1. **Add regression coverage for the new overview interaction before implementation.** Update `frontend/src/v2/components/GameDetails/OverviewTab.test.ts` to cover the read-only state, including the resolved `summary` being rendered as normal text, the editor not being mounted before activation, and the pencil control exposing an accessible edit label/test hook when `rom.edit` is granted. Cover the denied-permission state so no pencil action is offered while the read-only description remains visible. Assert that activating the pencil opens the existing editor surface with the ROM id, expected version, manual metadata, provider metadata, fallback description, and provider-authority flag unchanged. Keep tests aligned with the existing no-Pinia mount guard used by the shared editor.

2. **Move parent-ROM manual editing behind the pencil action.** Modify `frontend/src/v2/components/GameDetails/OverviewTab.vue` to derive the same scoped `useCan("rom.edit", { kind: "rom", id: rom.id })` permission used by the editor, render `summary` only as read-only overview text, and show an accessible `mdi-pencil-outline` `RBtn` only when editing is allowed. On activation, open an `RDialog` using the existing mobile/fullscreen behavior and place the unchanged `LocalizedDescriptionEditor` inside it. Close the dialog after a successful save while retaining the current `@saved="emit('refresh')"` refresh path and preserving the editor's existing service, locale, reset/cancel, snackbar, and optimistic-concurrency behavior. Use existing translation keys (`common.edit` and `rom.description-editor`) and existing v2 primitives; do not create a second editor or a new mutation path.

3. **Apply the same scoped pattern to PC DLC descriptions and update focused tests.** Modify `frontend/src/v2/components/GameDetails/PcDlcDetail.vue` so its overview renders the computed component-resolved `summary` as read-only text with a permission-gated pencil trigger, opens the same existing editor in an `RDialog`, passes `componentId` and `component.updated_at` unchanged, and closes on successful component save plus refresh. Remove or repurpose only the old overflow-menu entry whose sole purpose was to reveal the always-mounted description editor; leave cover search, metadata matching, artwork, and download actions intact. Update `frontend/src/v2/components/GameDetails/PcDlcDetail.test.ts` to verify the editor is initially closed, the overview pencil opens it with the parent ROM scope and component id, denied `rom.edit` hides the trigger, and manual/provider/legacy summary precedence remains unchanged. Run the focused Vue tests and frontend typecheck.

**Files expected to change:**

- `frontend/src/v2/components/GameDetails/OverviewTab.vue`
- `frontend/src/v2/components/GameDetails/OverviewTab.test.ts`
- `frontend/src/v2/components/GameDetails/PcDlcDetail.vue`
- `frontend/src/v2/components/GameDetails/PcDlcDetail.test.ts`

**Acceptance criteria:**

- Parent ROM and PC DLC overviews show the resolved description as normal read-only text by default.
- A permission-authorized user can activate an accessible pencil action and gets the existing locale-aware `LocalizedDescriptionEditor` in the shared dialog surface.
- Users without the scoped `rom.edit` grant see no edit trigger, and existing backend authorization remains the source of truth.
- Saving still uses the existing ROM or PC component service/mutation, expected-version guard, snackbar behavior, and refresh event; successful save closes the editor surface.
- PC DLC editing remains scoped to the parent ROM permission and component id, with manual text winning over provider and legacy fallback text.
- Focused `OverviewTab` and `PcDlcDetail` Vitest suites and `cd frontend && npm run typecheck` pass.
