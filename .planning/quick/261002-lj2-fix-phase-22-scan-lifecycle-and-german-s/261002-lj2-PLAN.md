# Fix Phase 22 scan lifecycle, German Steam summary persistence, and DLC UAT fixture layout

## Objective

Correct the exact failures found in the disposable Phase 22 browser UAT without
weakening queue concurrency protection or expanding the UAT safety boundary.
Pending automation evidence must be captured from the final durable target
version of that scan. Steam's already confirmed German Storefront description
must survive the scan persistence path. The next UAT fixture must express a
scanner-recognized parent game with a DLC child, so the browser can verify the
real component flow.

Locked evidence:

- Pending evidence is currently saved before another write in the same scan
  advances the parent or component `updated_at`, making an immediate Skip
  incorrectly return `409 Conflict`.
- The UAT uses `STEAM_API_LANGUAGE=german` and country `CH`. Live appdetails
  for Steam ids `1091500` and `2138330` return German descriptions, yet the
  persisted catalog summary is English while provenance says German with no
  fallback.
- Flat Cyberpunk fixtures produce two parent ROMs. The scanner recognizes DLC
  only below the parent game's established component-directory layout.

Do not change Docker Compose source, use a persistent database, access a NAS,
Team4s, a real library, or real game bytes. Do not loosen ordinary review-item
claim/skip/requeue version checks, and do not add an endpoint, migration, or
browser-controlled queue transition. Preserve unrelated working-tree changes
and do not commit this quick task.


`process_*` calls `upsert_pending` using the `updated_at` from the supplied,
durable target. Therefore the scan must supply a target reloaded after every
same-scan mutation that can affect its optimistic version.

`summary`, structured `metadata`, and owned `media`. A summary in a preferred

listed in `steam_metadata.fallback_fields`.

recognized component root, and named directories beneath it become separate

## Safety and Security Boundaries

- Queue evidence remains entirely server-derived, version-bound, and subject
  to its existing strict review-action stale checks. This task corrects only
  the producer ordering that previously created self-stale evidence.
- Steam data remains an untrusted external provider response normalized before
  guarded catalog persistence. Existing manual and fallback protections remain
  authoritative.
- UAT bytes are synthetic text files in a fresh read-only temporary bind.
  Neither test nor procedure may access, modify, mount, or infer any real
  library or infrastructure outside the named disposable project.
