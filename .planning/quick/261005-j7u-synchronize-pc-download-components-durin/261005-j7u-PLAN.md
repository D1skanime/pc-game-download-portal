# Admit existing nested Windows ROMs to component-only quick rescans

## Objective

Make a normal, unscoped QUICK scan dispatch an existing directory-backed
Windows ROM to the already-correct `scan_rom` component-reconciliation path.
This persists the `base` component from `261005-h08`, including
`The Witcher 3 Wild Hunt.iso`, without treating other existing ROMs as full
rescans or refreshing provider metadata.

## Low-scope design

`should_scan_rom` currently only sees the persisted `Rom`, so it cannot tell
whether the matching filesystem entry is directory-backed. Add one optional
filesystem-shape argument, `fs_rom: FSRom | None = None`, rather than deriving
shape from a database field or broadening QUICK globally. At its sole batch
call site in `_identify_platform`, pass the current `fs_rom`. Preserve the
existing scoped-ROM-ID early return. For an unscoped QUICK scan, admit only an
existing ROM when all of these are true: its persisted platform slug is
`UPS.WIN`, the current `fs_rom` is supplied, and `fs_rom["nested"]` is true.
All other QUICK decisions remain unchanged. `_identify_rom` already avoids
`get_rom_files` for existing unscoped QUICK ROMs via `_should_get_rom_files`,
and `scan_rom` already reconciles nested Windows components after durable
persistence, so no handler, metadata, hash, or download code changes are
needed.

## Safety boundaries

- The change only makes a pre-existing, capability-bound scan path reachable;
  it does not write, rename, move, delete, or archive source-library files.
- Component persistence remains after durable catalog persistence, with the
  existing reconciliation failure isolation and owned-resource cleanup.
- No migration, package, API schema, frontend contract, external service, or
  provider behavior is introduced or changed.
