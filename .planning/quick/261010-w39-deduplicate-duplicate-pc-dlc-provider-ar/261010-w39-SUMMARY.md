# Content-based PC DLC provider media deduplication

Implemented safe content-based deduplication for PC DLC provider media while reusing the existing owned-media storage, database mutation, placement, and cleanup paths.

Changes:

- Provider image storage now validates once, computes SHA-256, and uses a versioned provider/role/content identity for deterministic filenames and persisted provider_media_id values.
- Automatic IGDB enrichment and manual PC metadata selection share the same identity helper; review candidate IDs remain request/display identifiers.
- RomComponentOwnedMedia.content_sha256 and a scoped lookup index were added through Alembic revision 0137_pc_component_provider_media_content_identity.
- Repeated imports are idempotent for the same provider, role, and content.
- Existing readable provider duplicates are reconciled only within the current DLC component/provider/role and only on exact SHA-256 equality.
- Placements are preserved, duplicate paths are returned only when unreferenced, and missing cleanup files remain tolerated.
- Upload-origin media, sibling components, other providers, different roles, unreadable files, and stale expected-version behavior remain scoped and untouched.
