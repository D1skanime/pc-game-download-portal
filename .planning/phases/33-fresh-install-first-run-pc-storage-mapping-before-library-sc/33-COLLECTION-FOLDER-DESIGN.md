# Phase 33 collection-folder correction

## Authorized behavior

The live UAT established that a normal PC scan may identify a collection directory, such as Castlevania, as one game. The administrator explicitly selects Belmont's Curse below that record through the existing deep-scan dialog. A successful selected-child scan must replace the incorrect parent catalog entry with that child, remove the parent's exclusively owned media, and remember the parent as a collection for future scans.

This correction does not infer collections from names or directory depth. An ordinary filesystem scope without explicit collection-promotion intent remains nondestructive. Unselected parents remain normal games. The later automatic discovery requirement was explicitly added by the user after the initial selected-child-only discussion and supersedes that earlier future-scan restriction. The initial manual promotion scans only the selected child. Later normal and scheduled scans discover the direct game children of that explicitly classified collection, including newly added siblings. Games stays read-only.

## Decisions

- C-01: Add optional `collection_promotion` to ScanOperationRequest. Its strict object contains parent_rom_id, mapping_id, expected_revision, parent_relative_path, selected_child_relative_path. The dialog supplies the existing parent record ID and mapping identity; the backend independently derives and compares normalized parent and child identities. Require the matching filesystem scope, one mapped platform, directory target strictly below the exact parent, and a filesystem-producing scan. Reject metadata_only, media_only and hashes promotion. Include the entire intent in canonical request identity. Existing requests without intent retain current behavior.
- C-02: Persist collection classification only at successful child final publication. Add `ScanCollectionFolder`, scoped to mapping ID plus a binding digest of storage_root_id and mapping.relative_path. Store full normalized relative paths and verify full values after digest lookup. Uniqueness uses fixed SHA-256 path digests to avoid oversized MySQL indexes. Retain actor and operation audit identities without a cascading ROM FK. No automatic import/backfill.
- C-03: Use one authoritative finalization transaction for the durable child publication/checkpoint, classification insertion, and exact parent catalog retirement. Revalidate mapping revision, active binding, parent identity, child existence and current attempt through checked_scan_write before mutation and before commit. Do not merely add a destructive call after record_completed_game has already committed. Prepare filesystem/media evidence outside SQL and use existing ScanMediaBatch publication composition. Earlier provisional child work may exist if finalization fails; parent and classification stay unchanged until finalization commits. Metadata warnings permit promotion when the child filesystem result is durable; fatal/cancelled/stale attempts do not.
- C-04: Reuse CatalogLifecycleHandler.remove_from_catalog(session=the_finalization_session) to retain saves, states and play sessions under RetainedCatalogIdentity and queue cleanup under OwnedCleanupIntent. Never use OwnedMediaCleanupIntent as the retirement outbox: its ROM FK cascades away. Do not transfer parent user state to the child. Snapshot parent notes, RomUser attributes and collection membership into a bounded retained audit payload before lifecycle deletion, rejecting promotion without truncation if the bound is exceeded so existing operator state remains recoverable; expose no new automatic inheritance behavior.
- C-05: Reuse the existing cleanup scheduler/outbox rather than introducing an independent queue. Extend its supported intent shape with an exact-file cleanup manifest for promoted parents, including parent incarnation, owned root, normalized file identity/content evidence and durable progress. Do not recursively remove the parent resource directory for promotion. Use OwnedDelete/content proof and the owned writer domain; recheck all live references across ROM, component, track, collection and screenshot ownership before every deletion. Any shared or ambiguous file is retained and reported; never unlink external URLs, source-backed media, Games paths or an entire unproven directory. Empty owned directories may be removed only with rmdir after verified exact-file cleanup.
- C-06: Whole-platform quick, complete and scheduled scans skip classified parents and enumerate their direct child game directories through one shared collection inventory service used by the canonical mapping executor and any existing watcher path. Each child directory remains one game; its internal files are not classified as additional games. Preserve child's complete logical path identity and missing-state handling. Before any scan-originated add/merge/update or retained-identity reconnect, apply the same classification guard inside the publishing SQL transaction. This covers metadata retry, stale normal scans and all durable/manual/scheduled scan entry points. No parallel resolver, scheduler, watcher inventory or scan lifecycle. New shared production modules target at most 500 logical lines, with thin legacy glue and no copied manual/scheduled implementations.
- C-07: Classification is bound to the exact mapping ID, root ID and mapping base path. A remap/deactivation does not silently apply an old decision elsewhere. The executing command still uses the current expected revision. Deleted or unreadable child directories follow existing missing/read-failure policy and never cause parent resurrection. Repeating the same successful selection is idempotent, including after the original parent row has been retired: a matching persisted decision and parent-incarnation audit are required for replay. A different live ROM reusing an ID is never retired by replay.
- C-08: On commit, immediately attempt bounded cleanup outside the transaction; failures remain durable for scheduler retry. The existing catalog cleanup task is manual-only, so its shared claimed-intent processor must also be reached by the already registered scheduled owned-media cleanup task. Do not assume a manual task retries automatically. A crash after commit must leave classification, child and outbox recoverable. Before commit, cancellation, lease loss, remapping or a failed child leaves parent metadata/media/classification unchanged. Cancellation after commit does not undo committed promotion.

## Existing contracts and extraction boundaries

`CatalogLifecycleHandler.remove_from_catalog(rom_id, *, actor_user_id, session=None)` already composes into a caller-owned transaction and preserves saves/states/play sessions. Its existing RESOURCE intent recursively removes an ID-based directory, so it cannot be used unmodified for promotion cleanup. `begin_session` enlists caller-provided sessions and scan fencing. `checked_scan_write(session)` locks the singleton execution slot and authoritative attempt and rejects cancellation, expiration and mismatched attempt. `ScanMediaBatch.publish_and_associate` accepts a synchronous session callback. `record_completed_game` currently opens a separate worker-update transaction; extract a session-aware successful-game finalizer.

New production modules each target at most 500 logical lines: model/contract, collection policy/finalization, scoped discovery, cleanup policy. Legacy scan.py and roms_handler.py receive thin delegation only. Do not duplicate mapping normalization, provider enrichment, existing ownership proof or retained-user-state logic.

## Acceptance matrix

1. Castlevania initially has erroneous metadata and owned cover. Explicit successful Belmont selection leaves one Belmont child, no Castlevania catalog game, one classification and the initial selected-child audit.
2. The initial manual action excludes other siblings. A later full scan discovers the collection's other direct children and a newly added child, retains Belmont, and does not recreate Castlevania. The existing scheduled scan does the same through the shared service; metadata retries cannot recreate the parent.
3. Generic scoped scanning without promotion does not remove or classify its parent.
4. Failed/empty/cancelled child, stale revision, lost lease and crash before final commit retain the parent and media; transaction rollback leaves no classification or deletion intent.
5. Crash after final commit and crash during cleanup recover through the same durable outbox. Duplicate execution changes no counts and cannot delete a replacement incarnation.
6. Remap to another root/base path, symlink escape, sibling path and prefix lookalike are rejected or excluded without source writes.
7. Child/other-game/collection shared media remain; unreferenced proven parent cover/manual/screenshots/owned media are removed eventually. Source-backed soundtrack/library files remain byte-identical.
8. Saves/states/play sessions remain attached to retained parent identity; notes, user flags and collection membership remain in retained audit, and none are silently attached to Belmont.
