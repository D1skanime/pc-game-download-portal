<threat_model>

## Attack Surface

Full catalog and migration API chain, v2 destructive UI, external read-only source, generated contract harness, database dialect boundaries, and concurrent lifecycle operations.

## Trust Boundaries

| Boundary                         | Risk                                                                                   | Mitigation                                                                                                                 |
| -------------------------------- | -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| v2/client to API                 | Forbidden mutation or stale confirmation reaches backend                               | Catalog-only types/UI, strict schemas, auth, version and fingerprint binding                                               |
| DB lifecycle to external source  | Removal/migration/rollback mutates archive                                             | Read-only capabilities, closed inventory, denial-before-I/O, before/after manifests                                        |
| concurrent actors to owned state | Reconnect/rollback/first-use races split ownership                                     | Deterministic locks, exact IDs, optimistic versions, atomic transactions                                                   |
| harness to local Docker          | Stale code, hostile entrypoint/env, secret disclosure, or another resource is targeted | Exact full-ID config/env parity, `/bin/sleep infinity`, redacted diagnostics, mode-0600 env file, and full-ID-only cleanup |

## Abuse Cases and Security Verification

- Direct mutation calls, hidden asset probes, equal-metadata byte substitutions, replay/cross-platform confirmations, same-count substitutions, symlink drift, stale rollback rows, malformed/missing PID state, and runner-identity tampering are all exercised.
- Public responses are allowlisted and path-free.
- Every failure is asserted to precede source I/O or leave owned state transactionally unchanged.
- Real MariaDB/MySQL/PostgreSQL runs prevent SQLite-only confidence.
  </threat_model>
