<threat_model>

## Attack Surface

Detached asset identifiers, public asset visibility, scan-observed logical paths and hashes, and concurrent retained identity claims.

## Trust Boundaries

| Boundary                              | Risk                                                                | Mitigation                                                                                   |
| ------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| client to asset API                   | Caller probes a hidden retained game or edits another user's asset  | Preserve owner checks and 404-mask effective retained platform visibility before file access |
| scan observation to retained identity | Weak or ambiguous metadata attaches saves/history to the wrong game | Exact normalized path or unique complete triple hash only, with no fallback                  |
| database to owned asset storage       | Detached path is mistaken for external source authority             | Continue to use only the composed ASSETS descriptor and validate stored owned paths          |

## Abuse Cases and Security Verification

- Spoofed partial hashes and duplicate retained identities are rejected by tests.
- Hidden-platform retained assets return indistinguishable 404 responses.
- Concurrent claims are serialized and never split saves, states, and sessions across ROMs.
- Source manifests and storage-authority spies prove no external read or mutation is introduced by asset lifecycle operations.
  </threat_model>
