<threat_model>

## Attack Surface

Post-commit dependency failures, attacker-controlled mapped relative paths, filesystem race errors, and disposable verifier-container lifecycle.

## Trust Boundaries

| Boundary                           | Risk                                                              | Mitigation                                                                                                                           |
| ---------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| committed DB state to Redis/cache  | Dependency failure makes success ambiguous                        | Return durable outcome; isolate and log best-effort invalidation                                                                     |
| filesystem exception to HTTP layer | Raw path/error leaks or unhandled 500                             | Complete bounded MappedReadError classification                                                                                      |
| harness to Docker daemon           | Spoofed config validates stale code or leaks database credentials | Inspect entrypoint/command/env/image/network/user/bind/workdir/ports by full ID, redact secrets, and clean only the full ID/env file |

## Abuse Cases and Security Verification

- Cache failures occur after confirmed commit and cannot alter response truth.
- Path escape, symlink race, invalid path, and non-directory errors contain no attacker-visible path.
- Missing/malformed PID state and runner preflight mismatch cause safe refusal without host process signals.
- Entrypoint, command, environment, or secret-redaction mismatch fails before start and still cleans the exact ID/env file.
- Cleanup remains idempotent and removes only the recorded full container ID and harness-owned volume/files.
  </threat_model>
