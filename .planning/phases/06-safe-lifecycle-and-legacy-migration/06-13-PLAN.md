<threat_model>

## Attack Surface

Rollback IDs/versions, persisted change records, concurrent catalog edits, mapping lineage, and cross-dialect transaction behavior.

## Trust Boundaries

| Boundary                                      | Risk                                                 | Mitigation                                                                                             |
| --------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| admin rollback request to migration           | Cross-platform or replayed token targets other state | Bind migration ID, platform ID, expected version, expiry, and unused state                             |
| persisted change set to live catalog          | Stale IDs overwrite newer or unrelated records       | Lock exact IDs, verify entity kind/platform/current produced value, fail whole transaction on mismatch |
| rollback to external archive                  | Recovery code mutates source                         | No descriptor construction or filesystem call in rollback; source manifests asserted equal             |
| transaction to non-transactional DDL dialects | Portability assumptions lose recovery metadata       | 0112 guards plus real MariaDB/MySQL/PostgreSQL round trips                                             |

## Abuse Cases and Security Verification

+- Forged entity kind/ID, missing rows, cross-platform IDs, duplicate change rows, and altered current values all fail closed.
+- Later-created rows and already-visible rows remain unchanged.
+- Rollback/first-use and rollback/catalog-change races have one ordered winner without sleeps.
+- Injected failures at mapping, catalog, audit, and state flushes leave no partial restoration.
</threat_model>
