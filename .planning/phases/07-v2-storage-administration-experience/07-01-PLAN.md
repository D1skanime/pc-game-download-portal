# Plan 07-01: Storage Administration Foundation

<objective>
Create the typed v2 integration layer and canonical administrator entry points for storage roots and platform mappings.

Purpose: make the existing storage API usable from a single v2 workflow without bypassing generated contracts or conflating active and unsaved mapping state.
Output: typed API/composable or store, access-controlled routes, and shared navigation context.
</objective>

<tasks>
<task type="auto">
  <name>Task 1: Add typed v2 storage administration data boundary</name>
  <files>frontend/src/v2/services, frontend/src/v2/stores</files>
  <action>Inspect generated storage contracts and existing v2 service/store conventions. Add the smallest typed boundary needed to list storage roots and mappings, browse folders, run manual tests, save changes, remove mappings, and obtain preview data. Keep API-provided relative folders as data; never construct absolute host paths. Model active data separately from a mutable draft so a failed test or cancelled edit cannot replace the active mapping.</action>
  <verify>Run the focused frontend typecheck and focused unit tests for the new service/store.</verify>
  <done>All required storage operations are exposed through typed v2 code with active and draft state separated.</done>
</task>

<task type="auto">
  <name>Task 2: Establish one canonical v2 administration route and entry context</name>
  <files>frontend/src/v2/router, frontend/src/v2/components/Settings, frontend/src/v2/components/Platform</files>
  <action>Follow the existing v2 router and permission patterns to add the canonical platform storage route described by the design contract. Make Settings and platform detail open the same workflow, with platform detail preselecting its platform. Restrict entry and actions to administrators, preserving existing non-admin behavior.</action>
  <verify>Run focused route/component tests and the frontend typecheck.</verify>
  <done>Settings and platform detail lead to one administrator-only storage workflow with correct platform context.</done>
</task>
</tasks>

<verification>
- Generated contracts remain the source of request/response types.
- No path traversal or absolute-path construction is introduced in the client.
- UI-01 and UI-06 have an implementation entry point.
</verification>
