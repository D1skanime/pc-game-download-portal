Use a reserved attempt-owned directory that cannot be served as public media. Manifest durability precedes all bytes, including capability-internal temporary bytes. Network, source copying, image validation/resize/conversion, hashing and bulk data writes happen outside SQL locks. Reuse the existing streaming/provider algorithms and OwnedCreate capabilities. Never buffer arbitrary videos/audio in memory.

Use attempt-unique immutable filenames within the existing allowed media-family directory. Manuals stay direct PDF/Markdown children of this ROM's manual directory, as required by _validated_manual_path; encode the attempt/batch token in their basename. Cover/screenshot/special/DLC paths retain their existing response shape and persisted-path authority. Update deterministic getters to respect committed references without discovering staged files. Stage all byte preparation in reserved owned space; the final bounded local capability publication step happens inside checked_scan_write together with the exact catalog association callback using that same SQL session. If the current OwnedCreate context must remain open while streaming to keep its temporary file invisible, enter it outside the lock, flush/validate before the lock, then exit/publish inside the checked transaction. The manifest records the exact private temporary basename before streaming; it is derived from the unique final basename and is never returned by public media getters. A crash before recording that basename permits only the existing capability's exact dot-final-basename plus 32-hex temporary-name grammar to be reconciled, confined to the manifest's single generated final basename. Reuse its descriptor-relative publication, do not build another storage authority. Add OwnedCreate.prepare_binary_file() in storage_access as a narrow explicit preparation seam over its existing _OwnedStagedPublication: return a prepared capability with file, private basename, publish() and abort(); publication retains its existing no-follow, no-clobber, fsync and indeterminate-publication behavior. Prepare/stream/flush/validate outside the fence, publish under it, and abort on every pre-publication exception. No raw-path writer or replacement storage authority.

Keep old references and files intact throughout staging. Successful publication makes only complete immutable files available; SQL atomically replaces references and records exact unreferenced-old-path cleanup intents in the existing outbox. Special-media provider metadata paths and soundtrack track_meta.cover_path must join this association transaction; metadata must not commit new file references ahead of successful publication. COMPLETE means force re-fetch despite existing files/unchanged URLs; remove the pre-download destructive block. Missing/failed provider responses preserve previous good references. An authoritative successful empty inventory can detach old scan-owned references and queue exact files, preserving uploads and suppressed candidates.

Before publish/crash: old catalog and old bytes survive; unused staging is recoverable. After publish/before SQL commit: complete new immutable files can be orphaned, old catalog stays valid on rollback. After SQL commit/before manifest retirement: committed references protect new files; recovery must query real catalog references before cleanup, never trust manifest state alone. Unknown commit outcome requires a fresh authoritative lookup, never immediate deletion. Publication or association failure rolls SQL back and leaves manifest-backed exact cleanup; old files are never restored by overwriting paths because they were never changed.

Recover via the existing owned-media cleanup scheduler, not another queue, lease owner or operation lifecycle. It calls the recovery helper to reconcile bounded manifests, skip live leased attempts, lock slot/operation in the same order, and inspect ROM resource fields, special-media metadata fields, parent/DLC owned-media rows and soundtrack references before unlink. A manifest may only authorize deletion of its exact generated unreferenced files and private staging children. Fenced attempt outputs that committed before cancellation stay protected. Once old references are detached, exact cleanup intents retain post-commit deletion responsibility even if the process dies before unlink. Claim/check/unlink serialization and reference recheck must prevent reassociation races. Reuse existing cleanup intent state/retry methods; make recovery retry safe for processing rows after interruption, including missing-file completion and bounded safe failures. Do not use catalog-wide RESOURCE directory cleanup, construct retained identities or delete resource trees. Ambiguous or malformed manifests fail closed with a safe diagnostic and retained files.
