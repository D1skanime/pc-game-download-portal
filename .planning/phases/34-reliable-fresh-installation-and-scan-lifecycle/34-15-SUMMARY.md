## Implemented protocol

ScanWriteContext remains frozen operation/attempt/lease-owner identity. checked_scan_write locks the seeded slot before the operation, validates current running ownership and lease, and rechecks at flush/commit. The decorator reuses explicit sessions and has no second transaction. Operation repository transitions remain the existing authority.

A bounded durable manifest precedes private staging bytes. Network streaming, source copying, image transformation, hashing and pre-publication fsync precede publication locks. The final bounded capability publication and association callback use the same checked SQL transaction. Files have immutable generated basenames. SQL replaces references and records exact retired-path cleanup intents; SQL rollback cannot undo filesystem publication.

Recovery hashes before acquiring SQL locks, including under a bound scan caller. It then serializes attempt/reference inspection and unlink. It skips leased attempts, checks actual ROM, metadata, parent/DLC media and soundtrack references, and only removes exact proven unreferenced objects. The existing cleanup scheduler handles interrupted processing intents and missing files. Unknown or malformed evidence is retained.

A separate publication_started flag distinguishes attempted publication from abort. Non-scan Steam preserves the omitted session keyword contract and never removes possibly committed output after an association acknowledgement or cleanup-intent failure. Optional pre-publication failures still retain prior references.
